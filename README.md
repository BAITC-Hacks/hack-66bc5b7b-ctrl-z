# Электрокомплект — консультант по каталогу

Прототип по кейсу HackAlem AI: чат, поиск, характеристики и остатки ekt.kz, объяснимый предварительный подбор аналогов и корзина с явным подтверждением. Объяснение задачи и сценарий защиты — в [CASE.md](CASE.md).

## Запуск

Нужен Node.js 24 и npm. В каталоге проекта:

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local` и заполните выданные организатором `EKT_API_USER`, `EKT_API_PASSWORD`. Они используются только сервером. В архиве пароля нет. Без настроек поиск по сохранённой выборке доступен, а изменение корзины блокируется, поскольку проверить свежий остаток невозможно.

```sh
npm run build
node scripts/migrate-local.mjs
npm run dev
```

Откройте адрес, напечатанный сервером, обычно `http://localhost:5173`. Миграцию выполняйте один раз для новой локальной базы. Для проверки собранного Worker используйте `npm start`. Локальная D1 хранится в `.wrangler/state`.

```sh
node --experimental-strip-types scripts/test.mjs
npx tsc --noEmit
```

Интеграционные проверки требуют запущенного локального сервера и доступа к EKT API. Они создают отдельные тестовые сессии демонстрационной корзины; реальных заказов не создают.

## Архитектура

Интерфейс React → серверные маршруты Vinext/Cloudflare Worker → API ekt.kz + D1. Клиент не получает BasicAuth и не может самостоятельно задать цену. Данные каталога импортированы в `data/catalog.json`; `lib/domain.ts` отвечает за нормализацию, поиск, правила подбора и количества. `app/api/assistant/route.ts` обрабатывает диалог и двухэтапное добавление. `lib/store.ts` изолирует D1.

Сессия идентифицируется случайной HttpOnly cookie с SameSite=Strict и Secure на HTTPS. Запросы изменения требуют совпадения Origin. Серверное предложение содержит ID товара, количество, цену, случайный токен и срок пять минут. Подтверждение повторно читает API, проверяет доступное количество вместе с уже добавленным. Изменившаяся цена требует нового согласия. Обновление строки D1 использует сравнение revision: конкурентные подтверждения не могут оба записать одну версию состояния.

Диалог и корзина живут до 24 часов. Просроченные сессии удаляются при обращениях к приложению. Для настоящего магазина нужны его авторизация, согласованная политика хранения, лимиты на уровне инфраструктуры, мониторинг и нагрузочное тестирование.

## Данные и достоверность

Выборка: 100 реальных карточек с первых пяти страниц, полученных 2026-09-23. В неё входят цены, остатки по складам, свойства, описания, URL и изображения. Публичные изображения загружаются напрямую с ekt.kz. Ответы о товаре и изменения корзины запрашивают `/api/products/detail?id=...`. Поиск остаётся по выборке, поэтому «не найден» не означает «нет в магазине». В API нет найденного товара — неизвестные значения не подменяются нулями.

Пересоздать выборку можно скриптом ниже, передав доступ через переменные окружения оболочки. `CATALOG_PAGES` по умолчанию равен 5. Скрипт последовательно перебирает страницы и загружает карточки с параллелизмом четыре.

```sh
node scripts/sync-catalog.mjs
```

Скрипт не читает `.env.local` автоматически; экспортируйте `EKT_API_USER`, `EKT_API_PASSWORD` в окружение. После изменения выборки пересоберите приложение.

Подбор аналога требует совпадения группы каталога и минимум двух известных критических параметров; несовпадающий известный параметр исключает кандидата. Отсутствие противоречий не доказывает совместимость. Полная электробезопасность требует инженерной проверки. При противоречии номинала между названием и полями автоматические аналоги не выдаются.

Условия покупки сверены с публичным [разделом сайта EKT](https://ekt.kz/catalog/kabelenesushchie_sistemy/kabel_kanal/). Конкретные сроки, тарифы доставки и применимость способов оплаты уточняются при оформлении. Сертификаты не выдумываются: при отсутствии ссылки в API пользователь направляется к менеджеру.

## Подключение ИИ

Ключ не предоставлен, поэтому по умолчанию включён детерминированный поиск и ответы по каталогу. Для модели задайте на сервере:

```dotenv
LLM_URL=https://your-provider.example/v1/chat/completions
LLM_API_KEY=your-server-secret
LLM_MODEL=your-supported-model
```

Провайдер должен принимать совместимый с Chat Completions формат `messages` и возвращать `choices[0].message.content`. Модель преобразует запрос и до четырёх последних сообщений в JSON с поисковым запросом. Цены, наличие, итоговый фактический ответ и все действия корзины определяются сервером. При ошибке модели остаётся поиск без неё. Это ограниченный безопасный адаптер понимания запросов, а не проверенный автономный агент с полноценной генерацией консультаций.

Для JPEG нужна модель, принимающая `image_url` с data URL. Фотография отправляется выбранному провайдеру только после подключения; без ключа интерфейс объясняет ограничение. Подключённому провайдеру также передаются сообщения для разбора запроса — это нужно отразить в политике магазина. Не отправляйте платёжные данные в чат.

## Вложения

До 4 МБ: DOCX, XLSX, текстовый PDF до 25 страниц, TXT, CSV; JPEG после подключения модели. DOCX/XLSX разбираются как ограниченный ZIP/XML без выполнения макросов, формул и инструкций. Старые бинарные `.doc`/`.xls` не поддерживаются: сохраните как DOCX/XLSX. PDF-сканы без текстового слоя требуют OCR; без ИИ предлагается ввести артикул вручную. Распознанный текст ограничен 12000 символами, в поле запроса помещаются первые 2000. Файлы не сохраняются; пользователь проверяет текст и выбирает строку спецификации. Пакетный импорт всех строк в корзину не реализован.

## Границы прототипа

- Корзина собственная, не интегрирована в ekt.kz: предоставлены только методы чтения товаров. Ссылка `/#cart` открывает актуальную демонстрационную корзину той же сессии. Нет оплаты, реального заказа или резервирования.
- Полноценный LLM и OCR не проверены без ключа. На демонстрации режим честно подписан как поиск по каталогу.
- Интерфейс — отдельная адаптивная страница. Для виджета на сайте требуется адаптер сессии/корзины и согласованный способ встраивания; пока он не установлен на ekt.kz.
- Сертификат выводится только при наличии данных. Производственные правила доставки, кратности и допустимых складов нужно согласовать с владельцем каталога.
- Автоматические тесты покрывают основной цикл корзины, но не являются аудитом безопасности и нагрузочным испытанием.

## Проверяемые сценарии

`scripts/test.mjs`: точный артикул, расхождение 160/250 А, реальный аналог отсутствующего товара 24166, нулевое и превышающее остаток количество, запрет неявного согласия, отмена, повторное и конкурентное подтверждение, сохранение корзины, изоляция сессий, отклонение чужого Origin, уточнение параметров и чтение DOCX. Фронтенд предоставляет WebMCP `search_catalog` только для поиска: инструмент не меняет корзину.
