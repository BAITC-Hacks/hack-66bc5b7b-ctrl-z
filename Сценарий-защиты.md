# Электрокомплект — сценарий защиты на 3 минуты

Откройте EKT-demo.html в браузере. Это автономная репетиция по снимку каталога, а не запись работающего приложения. Два участника: первый выступает, второй переключает шаги. При одном выступающем используйте стрелки клавиатуры. Автопоказ — для короткого предварительного просмотра; на защите удобнее переключать вручную.

## 0:00–0:25 — проблема
«Здравствуйте! Мы команда Ctrl Z. Наш проект помогает покупателям Электрокомплекта получить характеристики, проверить наличие и подобрать предварительную замену в одном чате. Сейчас такие вопросы часто требуют обращения к менеджеру, и путь к покупке затягивается».

## 0:25–0:40 — готовность решения
«В прототипе реализованы поиск по выборке каталога, правила подбора аналогов и демонстрационная корзина с подтверждением. Адаптер языковой модели подготовлен, но без ключа используется поиск и шаблонные ответы. Сейчас покажем автономный сценарий по сохранённым данным».

## 0:40–1:05 — шаг 1
Введите на живом сайте «Есть товар 515291?» или покажите первый экран репетиции.
«Товар найден. Система отмечает противоречие: в названии указано 160 А, в характеристиках — 250 А. Покупателю нужно уточнить номинал. Ассистент не скрывает расхождение».

## 1:05–1:30 — шаг 2
Запрос: «Подбери аналог 24166».
«В снимке исходная позиция отсутствует. Алгоритм предлагает 11452 УЗО ВД63 (2ф) 40А (30мА) Schn El (1) !!!, ID 18158. Совпадают ток, полюсы и напряжение. Это кандидат на замену, а не гарантия технической совместимости».

## 1:30–2:05 — шаги 3–5
На живом сайте откройте Подробнее у ID 18158, выберите 1 штуку, нажмите Добавить…; отмените, затем повторите и нажмите Да, добавь.
«Сначала система запрашивает согласие. Счётчик корзины остаётся нулевым. Отмена тоже ничего не добавляет. Только явное подтверждение разрешает изменение. В серверном коде предусмотрена повторная проверка цены и остатка. Автономная репетиция API не вызывает».

## 2:05–2:25 — шаги 6–7
«В демонстрационной корзине одна позиция. При запросе ста тысяч штук система должна отклонить добавление из-за превышения остатка. Реальные заказы и резервирование этот прототип не выполняет».

## 2:25–3:00 — завершение
«Проект показывает основной путь от консультации до корзины. Для внедрения нужны интеграция с корзиной и сессией ekt.kz, подключение и проверка модели. На пилоте мы предлагаем измерять точность ответов, время консультации и долю обращений, решённых без менеджера. Сейчас бизнес-эффект ещё не измерен».

## Ответы на вопросы жюри
- Где здесь ИИ? Подготовлен адаптер модели для разбора запроса; без ключа работает детерминированный поиск. Работа подключённой модели в этой подготовке не проверялась.
- Данные реальные? В архиве 100 карточек; README указывает загрузку из API 23 сентября 2026 года. Показ использует этот снимок, текущие цены и остатки не проверены.
- Корзина настоящего магазина? Нет, это самостоятельная корзина прототипа. Для внедрения нужен API корзины ekt.kz.
- Аналог точно совместим? Нет. Алгоритм сравнивает известные параметры и объясняет подбор; итог требует проверки специалистом.
- Есть сертификаты? Только если источник предоставляет ссылку. Отсутствующий сертификат не выдумывается.
- Все проверки пройдены? В этой подготовке выполнены локальные проверки поиска, расхождения параметров, подбора аналога, количества и распознавания подтверждения. Серверные, браузерные и интеграционные проверки исходного приложения не выполнялись.

## Перед живой демонстрацией
1. Запустить исходное приложение по README и настроить серверный доступ к API.
2. Проверить актуальный остаток ID 18158; в архиве 3 шт., но наличие может измениться.
3. Использовать чистую тестовую сессию. Не обещать добавление в настоящую корзину ekt.kz.
4. Проверить цикл «предложение → отмена → предложение → подтверждение → корзина».
5. Держать автономный HTML как явно обозначенный резервный сценарий. Он работает без интернета.
